## 1. Visão Geral do Projeto

Esta organização está dividida em:
- **Repositório Central ("roadmap-overview")**: Onde você encontrará a visão geral do cronograma, o roteiro de 10 módulos e links para cada módulo.
- **Repositórios dos Módulos**: Cada módulo do nosso roteiro (por exemplo, `modulo-01-introducao`, `modulo-02-variaveis`, etc.) possui seu próprio repositório com:
  - Objetivos e atividades específicas da semana.
  - Recursos chave (vídeos, PDFs, tutoriais, slides) em português.
  - Exemplos e exercícios práticos.

---

## 2. Cronograma e Liberação Gradual dos Módulos

O roteiro está organizado em 10 módulos, a serem liberados semanalmente:

- **Semana 1:** Introdução e Configuração do Ambiente  
- **Semana 2:** Variáveis, Tipos de Dados e Operadores  
- **Semana 3:** Controle de Fluxo – Condicionais e Laços  
- **Semana 4:** Estruturas de Dados Básicas e Tipos Customizados  
- **Semana 5:** Funções, Closures e Modularização  
- **Semana 6:** Algoritmos Simples e Resolução de Problemas  
- **Semana 7:** Algoritmos de Ordenação e Busca  
- **Semana 8:** Ownership, Borrowing e Lifetimes  
- **Semana 9:** Programação Funcional com Iterators e Closures  
- **Semana 10:** Projeto Prático e Revisão Geral

**Processo de Liberação:**  
- Cada repositório de módulo será mantido inicialmente como privado.  
- Na semana correspondente, o módulo será liberado (tornado público ou compartilhado com os colaboradores).  
- A liberação será anunciada por meio dos nossos canais de comunicação, como nosso grupo no WhatsApp.

## 3. Estrutura de Repositórios

### Repositório Central: `roadmap-overview`
- Contém o cronograma completo, visão geral dos módulos e links para os repositórios individuais.
- Instruções gerais de uso, normas de contribuição e informações sobre os canais de comunicação.

### Repositórios dos Módulos (Exemplos)
- `modulo-01-introducao`
- `modulo-02-variaveis`
- `modulo-03-controle-de-fluxo`
- … até `modulo-10-projeto-pratico`

Cada repositório de módulo terá:
- Um **README.md** específico com:
  - Objetivos do módulo.
  - Lista de atividades e exercícios.
  - Links e recursos chave (vídeos, PDFs, tutoriais, slides).
  - Instruções para rodar o código (ex.: comandos Cargo).
- O código-fonte dos exemplos e dos exercícios práticos.

---

## 4. Fluxo de Trabalho e Contribuição

### Branching e Pull Requests
- **Branches:**  
  Cada repositório deverá conter um branch principal (por exemplo, `main`) e, se necessário, um branch de desenvolvimento (`develop`).  
  **Observação:** Na branch `main`, os códigos devem estar organizados em pastas nomeadas com o nome do colaborador.
- **Pull Requests:**  
  As contribuições devem ser feitas via pull requests. Descreva claramente as alterações e referencie o módulo ou exercício que está sendo atualizado.
- **Issues:**  
  Utilize as issues para registrar dúvidas, sugerir melhorias ou reportar problemas encontrados, mantendo o fluxo de trabalho organizado.

### Reuniões Semanais
- Haverá um encontro online (aproximadamente 1 hora) para discutir dúvidas, compartilhar soluções e alinhar o progresso.
- Esse momento é ideal para apresentar desafios e discutir as melhores abordagens para os exercícios.

### Diretrizes para Contribuição
1. **Leia o README do repositório central e o README específico do módulo.**
2. **Crie uma branch para sua contribuição e, em seguida, abra um pull request com uma descrição detalhada.**
3. **Participe das revisões e discussões – tanto nos pull requests quanto nas reuniões semanais.**
4. **Caso tenha dúvidas, abra uma issue ou entre em contato através dos nossos canais oficiais.**

---

## 5. Comunicação

- **GitHub Issues:**  
  Utilize as issues de cada repositório para registrar dúvidas e sugestões.
- **Reuniões Semanais:**  
  Agendadas conforme o cronograma para discussão e resolução de dúvidas.
